# テストを書くときの決まり

このファイルは、上の `paths` に合うファイルを触るときだけ読まれる（パス限定の決まり）。決まりを足すときは、同じ形で `.claude/rules/<名前>.md` を作る。

- 期待値は要件から決める。実装に合わせて甘くしない
- 通る場合だけでなく、落とすべき物を落とすことも 1 本ずつ書く
- テストは公開の入口（関数・型・API）を通して振る舞いを確かめる。内部の実装に依存させない
- 時計・乱数・ネットワーク・ファイルは差し替えられるようにし、本物に書かない
- テストを消す・skip する・しきい値を緩める、をしない。直せないときは理由を PR に書く
