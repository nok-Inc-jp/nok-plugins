# 直し方

## よくある落ち方

| 落ち方 | 当たりのつけ方 | 1 か所の直し方 |
| --- | --- | --- |
| 呼ばれるべきで呼ばれない | description に、依頼の言い方が無い | description の「〜と言われたとき」に、落ちた依頼の言い方を 1 つ足す |
| 呼ばれるべきでないのに呼ばれる | description が広すぎる（「レビューして」だけ、など） | 範囲を狭める語を足す（「業務アプリの設計資料を」）か、「〜には使わない」を 1 文足す |
| 隣のスキルと取り合う | 2 つの description が同じ言い方を持つ | 片方から言い方を外し、違いが分かる語を入れる |
| 手順を飛ばす | 本文の手順に番号が無い・確かめの段が無い | 飛ばした手順に「返す前に確かめる：〜」を足す |
| 様式が崩れる | 様式が本文に無く、資料の奥にある | 本文の手順に「様式は references/x.md。見出しの文言を変えない」を足す |
| してはいけないことをする | 本文の「必ず守ること」に無い、または埋もれている | 「必ず守ること」の先頭に 1 行足す。それでも破るなら、フックで止める案を人に出す |
| haiku だけ落ちる | 手順が長く、判断の所に既定が無い | 選ぶ所に既定を書く（「迷ったら A」）。説明を足すより、決めることを減らす |

## 効いたかの決め方

- **対照を置く**：直す前の写しと直した後を、同じ命令で続けて流す。kanna の R6（takumi の kyoui-fires）では、同じ版が 5/5・3/10・1/5 と動いた。前の回の記録とだけ比べると、直しが効いたのか、時のぶれなのかが分からない。
- **回数**：呼ばれる率は 10 回以上で見る。呼ばれる率が 5 割でも、5 回続けて当たることは 3% ほどある。
- **p の値**：`eval_ledger.py` の比べは、差が偶然で起きる確率（Fisher の正確検定）を付ける。0.1 より小さければ「確か」。R6 の 8/15 → 15/15 は p<0.01。
- **呼ばれすぎ**：description を強めたら、隣のスキルの依頼（似ているが呼ばれない）も 10 回流し、呼ばれすぎていないことを確かめる。

## 直しすぎの見分け方

- description が 1,024 字に近づいた・言い方の羅列になった → 足すより、似た言い方を 1 つにまとめる。
- 本文が 500 行に近づいた → 細かい物を references/ に出す。
- 落ちたケースの依頼文を、そのまま本文に書いた → そのケースにだけ効く直し（過学習）。言い方でなく、依頼の種類を書く。
- 呼ばれないケースが落ち始めた → 広げすぎ。前のラウンドに戻す。

## ラウンドの止め時

- 落ちたケースが通り、ほかが下がっていない → 締めの 1 回を sonnet で流して終わる。
- 3 ラウンド続けて上がらない → 止める。ケースの約束が本文とずれていないか、採点の誤りでないかを、人に確かめてもらう。
- 直すたびに別のケースが落ちる → スキルの範囲が広すぎる。スキルを分ける案を人に出す。
