# kanna-tune

eval を先に置いて、スキルを直す（公式の指針の「評価から作る」）。1 回のラウンドで 1 か所だけ直し、そのケースと、壊していないかを見るケースだけを流す。**通すために grader を直さない**（採点の誤りは kanna-eval-run の分けで「採点」とされた物だけで、直すかは人が決める）。

## 必ず守ること

- 1 ラウンドで直すのは 1 か所（description の 1 文、本文の 1 手順、など）。何を直したかを台帳の `--note` に書く。
- 直す前に、直す案と流すケースを見せて了承を取る（流すと利用料がかかる）。
- 流すモデルは haiku。haiku で通ってから、締めの 1 回だけ sonnet で流す。
- `evals/` の中（grader・prompt）は直さない。
- 3 ラウンド続けて上がらなければ止まり、分かったことを返す（同じ所を回し続けない）。
- 直した版は、プラグインの `CHANGELOG.md` に書く（版を上げるかは人が決める）。

## 手順

```
ラウンド N：
- [ ] 1. 落ちた理由を 1 つに絞った
- [ ] 2. 直す案と流すケースを見せ、了承を取った
- [ ] 3. 1 か所だけ直した
- [ ] 4. 流して台帳で比べた
- [ ] 5. 続けるか止めるかを決めた
```

1. 引数のフォルダは、作業フォルダ（今いる所）からの相対で探す。kanna の置き場（`${CLAUDE_PLUGIN_ROOT}`）の中を探さない。台帳（`<フォルダ>/evals/ledger.jsonl`）と最後の回の結果を読む。無ければ、依頼文に書かれた結果と、落ちたケースのファイル（`<フォルダ>/evals/<ケース>/` の prompt.md と graders）を読む。まず `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/harness_lint.py" <フォルダ>` を流す。落ちたケースの grader に必須の外れ（打ち誤った input_match の QE08 など）があれば、それは採点の誤りと決まる（読んで推し量らない）。そうでなければ、kanna-eval-run の `references/run-protocol.md` の「落ちた理由の分け方」（流し方 → 採点 → プラグイン）で分ける。**「プラグイン」と分けた物だけを直す**。流し方か採点なら、直さずにそう返して止まる。[references/tuning.md](references/tuning.md) の「よくある落ち方」から、いちばん当てはまる理由を 1 つ選ぶ。
2. 直す案（前と後の文）と、流すケース（落ちたケース・同じスキルの呼ばれないケース・近くのスキルの呼ばれるケース）を見せ、了承を待つ。
3. 了承をもらったら、スキルのファイルの 1 か所だけを直す。
4. 直す前の写し（対照）を作業フォルダの `.kanna/control/` に置き、対照と直した後を、`kanna_run.py run`（kanna-eval-run の手順）で、**同じ引数で続けて**流す（`--model haiku`。呼ばれる・呼ばれないのケースは `--runs 10`、ほかは `--runs 3`）。前の回の記録とだけ比べない（同じ版でも、時によって呼ばれる率が 3 割から 10 割まで動いた）。直した後の回の `--note` は `"R<N>: <直した所>"`。対照の回は、対照のフォルダの台帳に入る。
5. 対照と比べ、台帳の比べ（p の値つき）も読む。落ちたケースが「確か」に上がり、ほかが下がっていなければ、そのラウンドは採る。「ぶれの範囲かも」なら、回を増やして流し直してから決める。下がったケースがあれば、直しを戻して別の理由を試す。

## 返す形

```
## ラウンド
| R | 直した所 | 流したケース | 前 → 後 | 採ったか |

## 今の状態
合格 N/M（haiku）／ 締めの sonnet：未・済（合格 N/M）

## 分かったこと
- <直しても上がらなかった理由の見立てなど>
```
